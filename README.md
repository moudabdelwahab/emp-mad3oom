# نظام عمليات الموظفين — منصة مدعوم

نظام داخلي لإدارة حضور موظفي مدعوم وقياس نشاطهم الفعلي داخل بيئة العمل.
عربي بالكامل، RTL، بوضع فاتح وداكن.

---

## ما هو هذا النظام

يجيب النظام على أسئلة الإدارة اليومية بأرقام لها مصدر في قاعدة البيانات:

- من بدأ العمل ومتى، ومن أنهى ومتى.
- كم استغرق الشيفت فعليًا، وكم منه كان نشاطًا حقيقيًا داخل المنصة، وكم كان خمولًا.
- الاستراحات: متى ولكم.
- ما العمليات التي نفّذها الموظف داخل مدعوم (تذاكر، ردود، تغيير حالات…).
- تقارير يومية وأسبوعية وشهرية، وسجل تدقيق كامل لا يمكن حذفه.

**وما ليس هو:** ليس أداة تجسّس. لا يسجّل ما يكتبه الموظف، ولا يصوّر الشاشة، ولا
يتتبّع الفأرة، ولا يراقب أي شيء خارج بيئة مدعوم. يقيس **أحداث عمل معرَّفة مسبقًا**
وعدّادًا رقميًا للتفاعل — لا أكثر.

## لماذا أُنشئ

قياس الحضور بـ"وقت فتح الصفحة" غير صادق: تبويب مفتوح ليس عملًا. والقياس الساذج
للنشاط يقع في ثلاثة فخاخ يعالجها هذا النظام بالتصميم:

| الفخ | المعالجة |
|---|---|
| الواجهة ترسل المدة فيمكن تزويرها | المتصفح لا يرسل أي مدة ولا أي وقت — كل الأوقات من ساعة الخادم |
| ثلاثة تبويبات = ثلاث ساعات لساعة واحدة | دفتر دقائق مفتاحه `(الموظف، الدقيقة)` — الدقيقة لا توجد مرتين |
| نقرة بعد غياب طويل تكسب الغياب كله | الترحيل يسبق تسجيل التفاعل الجديد، فتُقفز الفجوة |

## المعمارية

```
المتصفح  ──(JWT موقَّع)──▶  public.eo_*()  [SECURITY DEFINER]
                                  │  ١. الهوية من auth.uid()
                                  │  ٢. حالة الموظف (نشط؟)
                                  │  ٣. الرتبة (١٠ / ٥٠ / ١٠٠)
                                  │  ٤. قواعد سلامة البيانات
                                  │  ٥. الكتابة بوقت الخادم
                                  │  ٦. سجل التدقيق
                                  ▼
                            emp_ops.*  (RLS + قيود المحرك)
```

**القاعدة الحاكمة:** لا يملك أي دور عميل (`anon` / `authenticated`) صلاحية
`INSERT` أو `UPDATE` أو `DELETE` على أي جدول في النظام — إطلاقًا. حتى لو عدّل
الموظف JavaScript أو استدعى الـAPI مباشرةً بمفتاحه، لن يكتب صفًا واحدًا.

تفاصيل القرارات المعمارية وبدائلها في [`docs/01-architecture.md`](docs/01-architecture.md).

## الأدوار

| الدور | الرتبة | الصلاحيات |
|---|---|---|
| موظف | ١٠ | يبدأ وينهي شيفته واستراحاته، ويرى بياناته هو فقط |
| مدير / موارد بشرية | ٥٠ | يرى كل الموظفين والتقارير وسجل التدقيق، ويدير الشيفتات والفرق |
| مدير عام | ١٠٠ | كل ما سبق + إنشاء الموظفين وتغيير الأدوار وتعديل الحضور والإعدادات |

الصلاحية تُقاس بالرتبة لا باسم الدور، فإضافة دور جديد = صف واحد في جدول `roles`.

## التقنية

| الطبقة | الاختيار | السبب |
|---|---|---|
| الواجهة | HTML + CSS + JavaScript Modules | لا build step، لا اعتماديات وقت تشغيل، صيانة مباشرة |
| الحالة | لا إطار عمل | حجم المشروع لا يبرر إطارًا ضخمًا |
| الخلفية | PostgreSQL + PostgREST (Supabase) | المنطق قرب البيانات، والقيود تفرضها قاعدة البيانات |
| المصادقة | Supabase Auth | نفس حسابات مدعوم — لا تسجيل دخول ثانٍ |
| الجدولة | pg_cron | إغلاق الجلسات المهجورة وحساب الإحصاءات |
| اللحظية | Supabase Realtime | إشعار بالتغيير فقط — قاعدة البيانات تبقى مصدر الحقيقة |

المكتبة الخارجية الوحيدة `supabase-js` **مُضمَّنة في المستودع** (`js/vendor/`)،
فلا يعتمد التشغيل على أي CDN.

## التركيب

```bash
git clone <repo> && cd mad3oom-employee-operations

# ١) قاعدة البيانات — بالترتيب
supabase link --project-ref <ref>
supabase db push          # أو نسخ ملفات supabase/migrations/ في SQL Editor

# ٢) الإعدادات
#    عدّل SUPABASE_URL و SUPABASE_ANON_KEY في js/config.js

# ٣) التشغيل محليًا
python3 -m http.server 8899   # ثم افتح http://127.0.0.1:8899
```

خطوات التحقق بعد الترحيل والنشر على Vercel في
[`docs/07-deployment.md`](docs/07-deployment.md).

### متغيرات البيئة

المشروع ثابت ولا يحتاج متغيرات على الخادم. القيمتان الوحيدتان في `js/config.js`:

| المفتاح | ملاحظة |
|---|---|
| `SUPABASE_URL` | رابط المشروع |
| `SUPABASE_ANON_KEY` | مفتاح `publishable` — **عام بطبيعته**، والحماية خلفه في RLS |

> `SUPABASE_SERVICE_ROLE_KEY` غير موجود في المستودع ولا يحتاجه النظام.
> `js/config.js` يوقف التطبيق إن اكتُشف مفتاح خدمة فيه.

## الاختبارات

```bash
supabase db execute -f tests/01_attendance_activity_engine.sql   # ٢٤ حالة
supabase db execute -f tests/02_security_and_integrity.sql       # ٢٤ حالة

npm i playwright-core && python3 -m http.server 8899 &
node tests/ui-smoke.mjs                                          # ٨ صفحات
```

اختبارات الخلفية تجري على قاعدة بيانات حقيقية داخل معاملة تُلغى بالكامل، فلا
تترك أثرًا. التفاصيل وما لم يُختبر في [`docs/09-testing.md`](docs/09-testing.md).

## التكامل مع مدعوم

منصة مدعوم لا تُعدَّل. يُنسخ إليها ملف واحد:

```js
import { Mad3oomActivity } from './mad3oom-activity-client.js';
import { supabase } from './lib/supabaseClient';

Mad3oomActivity.init({ supabase });
Mad3oomActivity.track('ticket_reply', { entityType: 'ticket', entityId: id });
```

التفاصيل في [`docs/08-integration.md`](docs/08-integration.md).

## ملاحظة على القياس

النظام يقيس **النشاط داخل المنصة**، ولا يزعم قياس إنتاجية الموظف ولا جودة عمله.
معادلة النسبة معروضة نصًّا في كل شاشة تعرضها، ولم تُستخدم كلمة "الإنتاجية" في أي
مكان في الواجهة.
