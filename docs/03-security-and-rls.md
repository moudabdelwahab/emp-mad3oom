# الأمن والصلاحيات

## النموذج في سطر واحد

> الواجهة لا تملك صلاحية كتابة واحدة على أي جدول. كل تغيير يمرّ عبر دالة على
> الخادم تحدد هوية المنفّذ من التوكن الموقَّع، وتفحص رتبته، وتكتب بتوقيت الخادم،
> وتسجّل العملية في سجل لا يمكن حذفه.

## الطبقات الأربع

### ١) صلاحيات Postgres — خط الدفاع الأول

```sql
revoke all on all tables in schema emp_ops from anon, authenticated;
grant select on <١٨ جدولًا> to authenticated;     -- قراءة فقط، محكومة بـ RLS
revoke usage on schema emp_ops from anon;         -- الزائر لا يرى المخطط أصلًا
alter default privileges in schema emp_ops revoke all on tables from anon, authenticated;
```

**النتيجة المُتحقَّق منها:** عدد صلاحيات الكتابة (INSERT/UPDATE/DELETE/TRUNCATE)
الممنوحة لأي دور عميل على أي جدول في `emp_ops` = **صفر**.

حتى لو عدّل الموظف JavaScript، أو استخدم مفتاح anon مباشرة من Postman، أو كتب
سكربتًا خاصًا — لن يستطيع كتابة صف واحد. لا توجد صلاحية أصلًا.

### ٢) RLS — من يرى ماذا

كل الجداول الـ١٨ عليها RLS مُفعَّلة، وسياسات **قراءة فقط** (لا توجد سياسة
INSERT/UPDATE/DELETE واحدة في النظام كله):

| الجدول | من يقرأ |
|---|---|
| `employees` | الموظف نفسه، أو من رتبته ≥ ٥٠ |
| كل جداول الحضور والنشاط والإحصاءات | `emp_ops.can_view_employee(employee_id)` |
| `app_settings` | الإعدادات العامة للجميع، والداخلية لرتبة ≥ ٥٠ |
| `audit_logs` | رتبة ≥ ٥٠، أو الموظف يرى ما نفّذه هو فقط |
| الكتالوجات (`roles`, `shifts`, `teams`, …) | كل موظف مسجَّل |

الدوال المستخدمة في السياسات (`current_employee_id`, `can_manage`) مُعرَّفة
`SECURITY DEFINER` — وإلا لدخلت في حلقة RLS لا نهائية على جدول `employees` نفسه.

### ٣) دوال RPC — من يفعل ماذا

٣٤ دالة في مخطط `public` بسابقة `eo_`، كلها:
- `SECURITY DEFINER`
- `SET search_path = emp_ops, public, pg_temp` (يمنع اختطاف المسار)
- `REVOKE ... FROM public, anon` + `GRANT EXECUTE TO authenticated`

**تم التحقق:** `anon_can_execute = false` على الـ٣٤ دالة بلا استثناء.

الرتب المطلوبة:

| العملية | الرتبة |
|---|---|
| بدء/إنهاء شيفت واستراحة · النشاط · بيانات الموظف نفسه | ١٠ (موظف) |
| لوحة الإدارة · التقارير · الفرق والشيفتات · سجل التدقيق · إنهاء شيفت إداريًا | ٥٠ (مدير) |
| إنشاء موظف · تغيير دور · تغيير حالة · تعديل حضور · الإعدادات | ١٠٠ (مدير عام) |

قيود إضافية داخل الدوال:
- لا يستطيع أحد تغيير **دوره** أو **حالة حسابه** بنفسه.
- الموظف الموقوف (`suspended`) أو المؤرشف تُرفض كل عملياته من `require_employee()`.
- `eo_report` يُعيد توجيه أي طلب من موظف عادي إلى بياناته هو، مهما مرّر من معرّفات.

### ٤) القيود على مستوى المحرك

مذكورة في [`02-database.md`](./02-database.md). حتى لو أخطأت دالة، تبقى قواعد
سلامة البيانات مفروضة من المحرك نفسه.

## منع التلاعب — الحالات المُغطّاة

| المحاولة | ما يمنعها | حالة الاختبار |
|---|---|---|
| تزوير `started_at` لبدء الشيفت مبكرًا | العميل لا يمرّر أي وقت؛ كل الأوقات `now()` على الخادم | ح٥ |
| تعديل سجل حضور مباشرة | لا صلاحية UPDATE | ح٥ |
| حذف سجل حضور | لا صلاحية DELETE | ح٦ |
| تضخيم `activity_minutes` | لا صلاحية UPDATE | ح٧ |
| فتح شيفتين لمضاعفة الساعات | فهرس فريد جزئي | ت٣، ح٢٤ |
| فتح عدة تبويبات لمضاعفة النشاط | مفتاح `(employee_id, minute_start)` + `marked_until` على مستوى الموظف | ت٩ |
| نقرة واحدة بعد خمول طويل لكسب الفجوة | الترحيل يسبق تسجيل التفاعل الجديد | ت٨ |
| إرسال آلاف النبضات | نافذة زمنية + حد نداءات على الخادم | ت١١ |
| رفع الرتبة ذاتيًا | لا صلاحية UPDATE + فحص داخل الدالة | ح٩ |
| قراءة بيانات زميل | RLS + فحص رتبة في الدالة | ح١، ح٢، ح٣، ح١١ |
| مسح أثر عملية من سجل التدقيق | trigger يرفض حتى من مالك الجدول | ح٨، ح٢٠ |
| تعديل شيفت مغلق | trigger `guard_closed_attendance` | ح٢٢ |
| تسجيل مدة سالبة | check constraint | ح٢٣ |
| العبث بساعة الجهاز | وقت العميل يُخزَّن للتدقيق فقط ولا يدخل أي حساب؛ `clock_skew_seconds` يفضح الفارق | — |

## الأسرار

- الواجهة تحمل مفتاح `publishable` فقط — وهو **مفتاح عام بطبيعته**، والحماية
  كلها خلفه في RLS والدوال.
- `SUPABASE_SERVICE_ROLE_KEY` **غير موجود في المستودع إطلاقًا**، ولا يحتاجه أي
  جزء من النظام. `js/config.js` يحتوي فحصًا يوقف التطبيق لو وُضع فيه مفتاح خدمة.

## XSS و SQL Injection

- **SQL Injection:** لا يوجد في النظام أي بناء استعلام بالنصوص. كل شيء عبر RPC
  ببارامترات مُطبَّعة الأنواع، وكل الدوال ذات `search_path` مثبَّت.
- **XSS:** الواجهة تبني DOM عبر `document.createElement` و`textContent`. لا
  يُستخدم `innerHTML` إلا لأيقونات SVG ثابتة معرَّفة في `js/utils/icons.js` —
  لا يمرّ أي محتوى من قاعدة البيانات أو من المستخدم عبر `innerHTML`.
- **إعادة التوجيه المفتوحة:** بارامتر `next` في صفحة الدخول يُفحص بتعبير نمطي
  يقبل المسارات الداخلية فقط.

## ما لا يفعله النظام (بالتصميم)

لا تسجيل لضغطات المفاتيح (تُعدّ عدًّا فقط)، ولا لقطات شاشة، ولا تتبّع للفأرة،
ولا مراقبة لأي شيء خارج بيئة مدعوم. الـ IP يُخزَّن على مستوى جلسة الجهاز فقط
لأغراض التدقيق الأمني ولا يظهر إلا لمن رتبته ≥ ٥٠.
