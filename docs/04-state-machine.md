# آلة الحالة

## الحالة ليست عمودًا — هي دالة

لا يوجد في النظام عمود اسمه "الحالة الحالية" يكتبه العميل. الحالة **تُشتق**
من أربع وقائع مخزَّنة، في دالة واحدة `emp_ops.compute_presence`:

1. هل توجد جلسة حضور مفتوحة؟
2. هل توجد استراحة مفتوحة؟
3. متى كان آخر تفاعل حقيقي؟
4. متى وصلت آخر نبضة؟

النتيجة: يستحيل أن تختلف الحالة بين لوحة الموظف ولوحة الإدارة والتقارير، لأن
مصدرها واحد.

## الانتقالات

```
                    ┌──────────────┐
                    │ NOT_STARTED  │  لا شيفت مفتوح ولا جلسات اليوم
                    └──────┬───────┘
                           │ eo_start_shift
                           ▼
        ┌────────────► ACTIVE ◄────────────┐
        │              │   ▲                │
        │  تفاعل حقيقي  │   │ تفاعل حقيقي     │ eo_end_break
        │              │   │                │
        │              ▼   │                │
        │            IDLE ─┘            ┌───┴────┐
        │   (مرّت عتبة الخمول            │ BREAK  │
        │    بلا تفاعل)                  └───▲────┘
        │              │                     │ eo_start_break
        │              │ توقفت النبضات        │
        │              ▼                     │
        │        DISCONNECTED ───────────────┘
        │              │
        │              │ eo_end_shift  ·  إغلاق تلقائي  ·  إنهاء إداري
        │              ▼
        │          ┌───────┐
        └──────────┤ ENDED │  لا شيفت مفتوح لكن توجد جلسات اليوم
                   └───────┘
```

## ترتيب الحسم

أول شرط يتحقق يفوز — والترتيب مقصود:

```
1. لا شيفت مفتوح   →  ENDED إن وُجدت جلسات اليوم، وإلا NOT_STARTED
2. استراحة مفتوحة  →  BREAK
3. آخر نبضة قديمة  →  DISCONNECTED
4. آخر تفاعل قديم  →  IDLE
5. غير ذلك         →  ACTIVE
```

**لماذا BREAK قبل DISCONNECTED؟** لأن الموظف في استراحته قد يغلق حاسوبه، ومن
غير المنصف أن يظهر "غير متصل" وهو في استراحة مسجَّلة رسميًا.

**لماذا DISCONNECTED قبل IDLE؟** لأن انقطاع النبضات معلومة مختلفة عن الخمول:
الخمول يعني "موجود ولا يعمل"، والانقطاع يعني "لا نعرف". الخلط بينهما يظلم
الموظف عند انقطاع الشبكة، ويضلل الإدارة.

## الحالات النهائية للجلسة

| الحالة | متى |
|---|---|
| `open` | جلسة جارية — واحدة فقط لكل موظف، يفرضها فهرس فريد جزئي |
| `closed` | أنهاها الموظف، أو أنهتها الإدارة بسبب مسجَّل |
| `auto_closed` | أغلقتها المهمة الدورية بعد انقطاع طويل، بوقت **آخر نبضة** |

الجلسة المغلقة لا يمكن تعديل أوقاتها إلا عبر `eo_admin_adjust_attendance`
(مدير عام + سبب إلزامي)، ويُحفظ القديم والجديد في سجل التدقيق وسجل أحداث الحضور.

## أثر كل انتقال

| الانتقال | ما يحدث فعليًا |
|---|---|
| بدء شيفت | صف جديد + حالة لحظية + حدث حضور + سجل تدقيق + إعادة حساب اليوم |
| بدء استراحة | ترحيل النشاط حتى اللحظة، ثم إيقاف الاحتساب |
| إنهاء استراحة | يُعدّ تفاعلًا حقيقيًا ⇒ تُفتح نافذة نشاط جديدة من الآن |
| إنهاء شيفت | إغلاق أي استراحة مفتوحة، ترحيل أخير للنشاط، إغلاق جلسات الأجهزة، إعادة حساب اليوم |
| إغلاق تلقائي | كما السابق، لكن وقت الانتهاء = آخر نبضة، مع حدث `shift_auto_close` وسجل تدقيق |
